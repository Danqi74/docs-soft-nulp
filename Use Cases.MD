Актори
Користувач
Система пошуку рейсів (Skyscanner-подібна платформа)

Передумови
Перед виконанням сценарію користувач повинен:

мати доступ до системи пошуку авіаквитків;
ввести параметри пошуку:
аеропорт відправлення;
аеропорт призначення;
діапазон дат подорожі.
Основний сценарій (Main Flow)
Користувач вводить параметри пошуку:
аеропорт відправлення (From);
аеропорт призначення (To);
діапазон дат (Start–End).
Система виконує перевірку коректності введених даних.
Система формує запит до зовнішніх джерел даних (авіакомпаній або GDS).
Система отримує список доступних авіарейсів, включаючи:
прямі рейси;
рейси з пересадками.
Система виконує агрегацію маршрутів, формуючи повні варіанти подорожей (multi-leg маршрути).
Виконується сортування результатів за критеріями:
ціна;
загальна тривалість;
час вильоту/прильоту.
Користувач отримує та переглядає список доступних варіантів перельоту.

Альтернативні сценарії

A1: Відсутність прямих рейсів

У випадку відсутності прямих рейсів система автоматично будує маршрути з пересадками через транзитні хаби.

A2: Відсутність рейсів у заданому діапазоні дат

Система пропонує користувачу:

розширити діапазон дат;
змінити аеропорт відправлення або призначення на найближчі альтернативні.
A3: Часткова недоступність API

У разі недоступності зовнішніх сервісів система використовує кешовані дані для відображення результатів.


Винятки (Exceptions)

E1: Некоректно введені аеропорти
→ система повертає помилку валідації та запитує повторне введення даних.
E2: Тайм-аут запиту до API
→ система виконує повторний запит або використовує резервне джерело даних (fallback).
E3: Відсутність доступних рейсів
→ система повертає порожній результат із повідомленням про відсутність варіантів перельоту.
